# R-5 — Eventi del vault durante operazioni massicce

> **Stato: PENDING** — in attesa di esecuzione su dispositivi reali. Prototipo costruito e type-checked, non ancora eseguito in Obsidian.

## Domanda

Quando in un vault da 10.000 file si sposta una cartella con 2.000 file, quali eventi del vault (`create`, `modify`, `delete`, `rename`) riceve un plugin, quanti, in quanto tempo e con che distribuzione? Arriva un `rename` per ogni file o uno solo per la cartella? Si perdono eventi?

## Ipotesi e criterio di successo

- **Ipotesi:** Obsidian emette un `rename` per la cartella e uno per ogni file e sottocartella contenuti (circa 2.000 + 21), in un'unica raffica di pochi secondi; nessun `delete`/`create` spurio.
- **Successo:** il numero di `rename` corrisponde al contenuto spostato (nessuna perdita), nessun evento spurio, e la raffica è abbastanza compatta da poter essere raccolta in un batch con un piccolo debounce.
- **Se fallisce** (da §10): batch più aggressivo e scansione di riconciliazione al posto degli eventi singoli.

## Setup

- Dispositivi: desktop (prioritario), iPhone, Android. Annotare versione di Obsidian.
- Vault di prova **vuoto e dedicato**, in memoria locale; plugin di spike installato: vedi [setup comune](README.md#setup-comune). Il server di prova **non** serve.
- Impostazioni del plugin: _R-5 synthetic file count_ = 10000, _R-5 files in the folder to move_ = 2000 (valori predefiniti).
- Struttura generata in `kamino-spike-mass/`:
  - `move-me/d000 … d019/` — 2.000 note (100 per sottocartella), la cartella da spostare;
  - `filler/d020 … d099/` — le restanti 8.000 note;
  - `moved-here/` — destinazione vuota.

## Procedura passo-passo

1. Comando `R-5: generate synthetic vault subtree`. Su mobile può richiedere diversi minuti: lasciare Obsidian in primo piano. La nota registra il tempo totale. Attendere qualche secondo che l'indicizzazione termini.
2. Comando `R-5: start counting vault events`.
3. Con l'esploratore file di Obsidian, **trascinare** `kamino-spike-mass/move-me` dentro `kamino-spike-mass/moved-here` (su mobile: pressione lunga sulla cartella → _Sposta file…_ / _Move folder to…_ → scegliere `moved-here`). Annotare a occhio la durata percepita e se l'interfaccia si blocca.
4. Attendere **30 secondi**, poi comando `R-5: write event counters (keep counting)`.
5. **Rinomina** della cartella spostata (`moved-here/move-me` → `moved-here/renamed`) con l'esploratore file; attendere 30 s; di nuovo `R-5: write event counters (keep counting)` (i contatori sono cumulativi: sottrarre i valori precedenti).
6. Variante ripetibile senza trascinamento: comando `R-5: delete the synthetic subtree`, poi di nuovo passo 1, `R-5: start counting vault events`, poi `R-5: move the folder via API (alternative to drag and drop)` (usa `fileManager.renameFile`, come l'interfaccia); attendere 30 s e `R-5: write event counters and stop counting`.
7. Facoltativo (solo desktop): con il conteggio attivo, aggiornare 2.000 file dall'esterno (es. `git checkout` di un ramo diverso o copia di una cartella con Esplora risorse/Finder) per vedere gli eventi generati da modifiche esterne o da plugin come Obsidian Git.
8. Pulizia: `R-5: delete the synthetic subtree` (la nota registra la durata della cancellazione ricorsiva).

## Impatto su ADR/requisiti

- **Eventi completi (≈ 2.021 `rename`), raffica compatta:** il plugin traduce gli eventi in operazioni con un debounce/batch breve; uno spostamento di cartella diventa un'operazione di rename per file (o una per cartella, se il protocollo la supporta). Da fissare in `03-sync-protocol.md`.
- **Solo il `rename` della cartella, non dei figli:** il plugin deve espandere lato client il rename della cartella nei path dei figli (dal proprio indice locale); da documentare nel protocollo.
- **Eventi persi, spuri (`delete`+`create`) o raffiche lunghe che bloccano l'interfaccia:** fallback di §10: batch più aggressivo con soglia (es. oltre N eventi in T ms si sospende la gestione evento per evento) e scansione di riconciliazione (confronto indice locale ↔ vault) al posto degli eventi singoli. Valutare una ADR sul rilevamento delle modifiche.
